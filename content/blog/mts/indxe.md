# MTS(Mobile Trading System) — 모바일 증권 트레이딩 앱의 구조와 기술

---

## 1. MTS란 무엇인가?

**MTS(Mobile Trading System)** 는 투자자가 스마트폰을 통해 주식·채권·파생상품 등 금융 자산을 매매하고, 시세를 조회하며, 계좌를 관리할 수 있는 모바일 트레이딩 플랫폼이다.

### HTS / MTS / WTS 비교

| 구분 | 풀네임 | 실행 환경 | 특징 |
|---|---|---|---|
| **HTS** | Home Trading System | PC 설치 프로그램 | 고기능, 빠른 처리, 전문 투자자 선호 |
| **MTS** | Mobile Trading System | 모바일 앱 (iOS/Android) | 언제 어디서나, 간편 인증, MAU 기반 경쟁 |
| **WTS** | Web Trading System | 웹 브라우저 | 설치 불필요, 기능 제한적 |

> 토스증권은 2021년 3월 MTS를 출시하며 쉽고 직관적인 UI/UX를 강점으로 빠르게 성장했고, 2024년 기준 토스 앱의 MAU는 2,480만 명을 돌파했다.

## 2. MTS 핵심 기능 구성

```
MTS 주요 기능
├── 계좌 관리
│   ├── 비대면 계좌 개설 (신분증 진위확인, 안면인식)
│   ├── 잔고 조회 / 손익 현황
│   └── 입출금 / 이체
│
├── 시세 조회
│   ├── 실시간 체결가 / 호가창
│   ├── 차트 (일봉·주봉·분봉)
│   └── 투자 정보 / 리서치
│
├── 주문 처리
│   ├── 국내 주식 (유가증권, 코스닥)
│   ├── 해외 주식 (미국, 일본, 중국 등)
│   ├── ETF / ETN / 채권 / 펀드
│   └── 파생상품 (선물·옵션)
│
└── 보안 / 인증
    ├── 간편 PIN / 생체 인증
    ├── 모바일 OTP
    └── 공동인증서 (구 공인인증서)
```

## 3. MTS 시스템 아키텍처

### 3-1. 전체 데이터 흐름

```
[거래소 (KRX)]
      │  시세 데이터 (멀티캐스트 / 유니캐스트)
      ▼
[시세 수신 서버]  ←── 외부 정보 벤더 (Reuters 등)
      │  데이터 가공·정제
      ▼
[Data Processor]
      │
      ├──▶ [Message Broker]  ──▶ [소켓 서버]  ──▶ 실시간 Push (WebSocket)
      │         (Kafka 등)
      └──▶ [Storage (DB/캐시)]
                                         ▼
                              [MTS 채널 서버]  ←── 부하 분산 (Load Balancer)
                                         │
                                         ▼
                                   [모바일 클라이언트]
```

> 토스증권은 마켓 데이터 수신 서버와 소켓 서버를 분리하여 AWS 환경에서 각각 독립적인 스케일링이 가능한 구조로 운영한다.

### 3-2. 주문 처리 흐름 (6단계)

```
① 투자자 → MTS 앱 접속
② 부하 분산 → MTS 채널 서버 연결
③ 채널 서버 ← 거래소 시세 수신 (실시간)
④ 채널 서버 → 투자자 단말에 시세 전송
⑤ 투자자 매매 요청 발생
⑥ AP 서버 → 주문 가능 금액·증거금 확인 → 거래소 주문 전달
```

### 3-3. 3-Tier 구조 상세

| 레이어 | 구성 요소 | 역할 |
|---|---|---|
| **프론트 시스템** | MTS 앱, 채널 서버 | 시세 수신, 사용자 인터페이스 |
| **미들웨어** | AP 서버, 리스크 관리 서버 | 주문 검증, 포트폴리오 분석, 리스크 관리 |
| **백오피스** | 계좌 DB, 결제 시스템 | 매매 전후 계좌 데이터 관리 |

## 4. 실시간 시세 처리 기술

### 4-1. 시세 데이터 전송 방식

| 방식 | 설명 | 특징 |
|---|---|---|
| **멀티캐스트** | 1개 송신 → 다수 수신 | 대용량 시세 배포에 효율적, 온프레미스 중심 |
| **유니캐스트** | 1:1 송수신 | 클라우드 환경에 적합, AWS 지원 |

클라우드 전환 시에는 멀티캐스트를 사용하기 위해 GRE 터널링과 PIM(Protocol Independent Multicast) 라우팅 프로토콜을 적용하거나, 유니캐스트 방식으로 전환한다.

### 4-2. 클라이언트 실시간 수신: WebSocket

```javascript
// MTS 실시간 시세 수신 예시 (개념 코드)
const ws = new WebSocket('wss://시세서버/realtime');

ws.onopen = () => {
  // 관심 종목 구독 요청
  ws.send(JSON.stringify({
    type: 'subscribe',
    stocks: ['005930', '000660'] // 삼성전자, SK하이닉스
  }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  // { code: '005930', price: 75000, volume: 1234, ... }
  updateStockPrice(data);
};

ws.onclose = () => {
  // 재연결 로직 (Exponential Backoff)
  setTimeout(reconnect, 3000);
};
```

### 4-3. 클라우드 기반 확장성 확보

온프레미스 인프라는 IPO 같은 대형 이벤트 때 급증하는 트래픽에 자원을 적시에 조달하기 어렵다. 클라우드 기반으로 전환하면:

- **예측 가능한 트래픽** (장 시작·마감 시간대) → 스케일링 스케줄링
- **예측 불가 트래픽** (IPO, 급등 이슈) → Auto Scaling
- **트래픽 감소 후** → 자원 자동 축소로 비용 절감

## 5. 보안 체계

금융 서비스의 특성상 MTS는 일반 앱보다 훨씬 엄격한 보안 레이어를 갖는다.

### 5-1. 인증 체계

```
인증 강도 (낮음 → 높음)
────────────────────────────────────────
PIN 번호 / 패턴
    │
생체 인증 (지문, 안면인식)
    │
모바일 OTP (M-OTP)
    │  ← 이체, 공동인증서 재발급 등 고위험 거래
공동인증서 (구 공인인증서)
    │
실물 OTP
```

### 5-2. OTP (One-Time Password)

- **Time OTP**: 시간 기반으로 30~60초마다 새 비밀번호 생성 → 금융기관에서 가장 널리 사용
- **Event OTP**: 버튼을 누를 때마다 비밀번호 생성 (횟수 기반)
- **모바일 OTP**: 실물 OTP 없이 앱에서 발급·사용 가능, 1인 1기기 1 OTP 원칙

### 5-3. 앱 보안 요소

| 보안 요소 | 내용 |
|---|---|
| **루팅/탈옥 탐지** | 임의 개조 단말에서는 앱 실행 차단 |
| **SSL Pinning** | 중간자 공격(MITM) 방지를 위한 인증서 고정 |
| **난독화** | 리버스 엔지니어링 방지 |
| **앱 위변조 탐지** | 공식 스토어 이외 경로 설치 감지 |
| **피싱 방지** | 개인화 이미지 등록으로 위장 사이트 식별 |

## 6. 국내 주요 증권사 MTS 전략 비교

| 증권사 | MTS 전략 | 특징 |
|---|---|---|
| **토스증권** | 플랫폼형 MTS | 직관적 UI, AI 기반 정보 제공, 콘텐츠 결합, 생활금융 확장 |
| **키움증권** | 거래 기능 중심 | 빠른 주문, 활성 트레이더 타겟, 수수료 경쟁력 |
| **미래에셋증권** | 글로벌 투자 강화 | 해외주식·선물옵션·연금 통합, 24시간 트레이딩 |
| **한국투자증권** | 글로벌 자산관리 | 해외 투자 다양화, 챗봇 연동 |
| **NH투자증권** | 사용자 경험 강화 | UX 개선 중심 |
| **삼성증권** | 고액자산가 타겟 | 자산관리 기능 집중 |
| **KB증권** | 자산 성장형 플랫폼 | 단순 거래 앱에서 투자 플랫폼으로 전환 전략 |

> 전반적인 트렌드: 단순 매매 도구 → **투자 플랫폼**으로의 진화. 송금·결제·환전 등 생활금융 기능까지 MTS에 통합하는 방향으로 경쟁 중.

## 7. 프론트엔드 개발자 관점: MTS의 기술 포인트

금융권 프론트엔드 개발에서 일반 서비스와 다르게 특히 신경 써야 하는 기술 요소들이다.

### 7-1. 실시간 데이터 렌더링 최적화

주식 앱은 시세·호가·체결 데이터가 초당 수십~수백 번 갱신된다.

```javascript
// ❌ 매번 전체 리렌더링 → 성능 문제
setStockData(newData);

// ✅ 변경된 부분만 업데이트
// React: useMemo, React.memo, useCallback 적극 활용
// 호가창처럼 고빈도 업데이트는 Canvas / requestAnimationFrame 사용 검토
```

### 7-2. WebSocket 연결 관리

```javascript
// 재연결 전략 (Exponential Backoff)
let retryDelay = 1000;
const MAX_DELAY = 30000;

function reconnect() {
  setTimeout(() => {
    connect();
    retryDelay = Math.min(retryDelay * 2, MAX_DELAY);
  }, retryDelay);
}

// 앱 포그라운드/백그라운드 전환 시 연결 관리
document.addEventListener('visibilitychange', () => {
  if (document.hidden) ws.close();
  else reconnect();
});
```

### 7-3. 금융 데이터 표시 주의사항

```javascript
// ❌ 부동소수점 오차 주의
0.1 + 0.2 === 0.3 // false!

// ✅ 금융 계산에는 정수 변환 또는 라이브러리 사용
// 가격: 원 단위 정수로 처리
// 수익률: toFixed(2) 사용 시 주의, 반올림 방식 명확히 정의

// 색상 컨벤션 (한국 증권 시장)
const priceColor = (change) => {
  if (change > 0) return '#FF3B30'; // 상승: 빨간색
  if (change < 0) return '#007AFF'; // 하락: 파란색
  return '#8E8E93';                 // 보합
};
// ※ 미국/유럽은 반대 (상승: 초록, 하락: 빨강)
```

### 7-4. 보안 관련 프론트엔드 제약

- **소스코드 난독화** 필수 (빌드 파이프라인에 포함)
- **민감 데이터 로컬 저장 금지** (계좌번호, 비밀번호는 메모리에만)
- **스크린 캡처 방지** (iOS: `UITextField.isSecureTextEntry`, Android: `FLAG_SECURE`)
- **키보드 보안** (금융 앱 전용 보안 키보드 적용 필수)
- **인증서 피닝** (네트워크 레이어에서 중간자 공격 차단)

## 8. MTS 개발 트렌드 (2025~2026)

- **AI 투자 어시스턴트**: 종목 분석, 포트폴리오 리밸런싱 제안 등 AI 기능 내재화
- **생활금융 통합**: 주식 매매 앱 → 결제·송금·환전까지 아우르는 슈퍼앱화
- **해외 주식 실시간 서비스 강화**: 미국 옵션 실시간 시세 등 글로벌 데이터 파이프라인 고도화
- **클라우드 네이티브 전환**: 온프레미스 IDC + 클라우드 하이브리드 → 풀 클라우드 이전 가속
- **접근성 강화**: 투자 입문자(2030)를 위한 UX 단순화, 투자 교육 콘텐츠 결합

## 9. 금융권 취업과의 연결고리

| MTS 기술 요소 | 금융권에서 요구하는 역량 |
|---|---|
| 실시간 WebSocket 아키텍처 | 저지연 시스템 설계 능력 |
| 채널 서버 / AP 서버 분리 구조 | 마이크로서비스 / 레이어 설계 이해 |
| OTP / 인증 체계 | 금융 보안 규제(전자금융거래법) 이해 |
| Auto Scaling / 고가용성 설계 | 장애 내성 시스템 설계 (SLA 99.9%+) |
| 프론트엔드 보안 (난독화, 피닝) | 금융 앱 보안 컴플라이언스 이해 |
